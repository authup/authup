# Reference: Keycloak

- **Project:** [keycloak/keycloak](https://github.com/keycloak/keycloak) — Red Hat's open-source IAM (Java).
- **Docs:** https://www.keycloak.org/documentation
- **Why referenced:** occasional design cross-checks (parity/posture comparisons); authup's primary
  parity target is Authentik (see `authentik.md`), Keycloak is consulted for OIDC/credential-storage
  precedent.
- **How to maintain:** when you look something up in Keycloak's docs/source during authup work, add
  or correct the mapping row here (cumulative). Pin claims to a version/date.

## Concept map (Keycloak → authup)

| Keycloak concept | authup counterpart | Behavioral differences / notes |
|---|---|---|
| User OTP secret storage: `CREDENTIAL` table, `SECRET_DATA` JSON column — **plaintext** (`{"value":"<seed>"}`; confirmed in [discussion #23207](https://github.com/keycloak/keycloak/discussions/23207), verified 2026-07-14) | `auth_user_authenticators.secret` — AES-256-GCM under the per-realm enc key from the realm key store (`auth_keys` `use=enc`, auto-generated, optionally KEK-wrapped via env `SECRETS_ENCRYPTION_KEY`; `select:false`) | authup encrypts TOTP seeds at rest; Keycloak does not (delegates to DB/disk encryption). |
| Realm keys (signing/encryption): generated per realm, private keys stored in `COMPONENT_CONFIG` — plaintext | `auth_keys.decryption_key` — plaintext base64, `select:false` only | Parity (both plaintext). Keycloak's own [secure-credentials-store design doc](https://github.com/keycloak/keycloak-community/blob/main/design/secure-credentials-store.md) lists realm keys, client secrets, LDAP/SMTP creds, IdP secrets, and user OTP secrets as "currently stored in plaintext". |
| Vault SPI (`${vault.key}` references) — **config-level secrets only** (SMTP password, LDAP bind credential, IdP client secrets); read-only lookup, shipped as Part I of the secure-credentials-store design | No vault indirection for config secrets; env/config values used directly | Part II of that design (an encryption/decryption SPI for DB-stored secrets, i.e. envelope encryption) was drafted but **never implemented** — Keycloak still stores user OTP secrets plaintext as of 2026. |
| Session device attribution: `UserSessionModel` exposes `getIpAddress()` with **no setter** (`server-spi/src/main/java/org/keycloak/models/UserSessionModel.java`, `main`, verified 2026-08-07). The address is fixed when the session is created / restarted (`restartSession(..., ipAddress, ...)`); a token refresh only moves `setLastSessionRefresh(int)` | `auth_sessions.ip_address` / `user_agent` pinned at creation; the refresh grant slides `refreshedAt` / `seenAt` / `expiresAt` only, and records the refreshing request on the `auth_session_tokens` row instead | **Aligned.** authup used to overwrite both columns from the refreshing request, which let a server-side refresher (the Nuxt console resolving the store during SSR) repaint a user's session as `node` plus the renderer's address. Keycloak's read-only accessor is the same call: the device belongs to the session, and refresh freshness is a separate field. |
| Event persistence: user (login) + admin events **not saved by default** (fire-only; written to server log via the built-in `jboss-logging` listener). When "Save events" is enabled per realm, `Expiration` defaults to **0 = never expire** (no default retention — [GH #47016](https://github.com/keycloak/keycloak/issues/47016), open as of 2026-07-16); current versions expose a separate admin-events Expiration (older ones lacked it, [GH #12476](https://github.com/keycloak/keycloak/issues/12476) stalled). Community guidance: short window (7–30 d) + external SIEM for long-term. | `auth_events`: persisted by default (`eventLogEnabled: true`), security events 90 d (`eventLogRetentionDays`, raiseable via config/env), entity-CRUD mirror 7 d (`eventLogEntityRetentionDays`), per-row `expires_at` + minute sweep; structured log line always fires (SIEM path) | authup is opt-out with bounded retention; Keycloak is opt-in with unbounded retention (table grows forever unless Expiration is set — known operational footgun). authup's default was 365 d (Authentik parity) until 2026-07-16, lowered to 90 d (Okta-parity, hosted-provider posture). Verified 2026-07-16. |
